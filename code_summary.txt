secure-iomt-platform code summary

Project purpose
---------------
This repository is a prototype IDS for an IoMT (Internet of Medical Things) system.
The IDS accepts Gateway-formatted JSON messages from medical devices, detects anomalies and attacks, and outputs standard alert objects for downstream systems.
The focus is on Gateway compatibility, alert schema compliance, and preserving a simple interface that can feed dashboards or LLM-based analysis.

Core files and responsibilities
-------------------------------
ids.py
  - Main IDS engine.
  - Parses Gateway JSON payloads for heart monitors.
  - Detects threats using four methods:
    * Data Injection: values outside a safe range (40-180 bpm) or invalid measurement format.
    * Device Spoofing: unknown device IDs or suspicious patient_id patterns.
    * DoS: too many messages from the same device within a short time window.
    * Isolation Forest anomaly detection on heart rate values.
  - Returns alert dictionaries or None for normal messages.
  - Provides a process_message helper for local test output.

alert_generator.py
  - Builds normalized alert JSON objects.
  - Ensures each alert contains exactly the required fields:
    alert_id, timestamp, device_id, alert_type, severity, anomaly_score, description, recommended_action.

isolation_forest_model.py
  - Trains an Isolation Forest on synthetic normal heart rate values.
  - Scores new measurements to detect statistical anomalies.

api.py
  - FastAPI web service exposing the IDS.
  - Endpoints:
    * POST /detect: accepts one Gateway message and returns either NORMAL or an alert.
    * GET /alerts: returns the list of alerts generated since the service started.
    * GET /health: service health check.

multi_device_dataset.json
  - Mixed multi-device input used by tests.
  - Contains heart monitor, thermometer, oximeter, and insulin pump messages with normal, Data Injection, Device Spoofing, and DoS examples.
  - Includes a valid `expected_label` field for evaluation metrics.

alert_payload.json
  - Generated alert payload written from the Gateway sample through the IDS.
  - Contains the actual alerts produced from the sample messages.

test_ids.py
  - Local test runner for the IDS.
  - Reads `multi_device_dataset.json`, sends each message to IDS, writes `alerts_output.json`, and optionally generates metrics.
  - Default sample is now `multi_device_dataset.json`.

test_alert_interface.py
  - Validates that the IDS can convert Gateway sample messages into valid alert JSON.
  - Writes `alert_payload.json` and checks each generated alert matches the required schema.

test_gateway_compatibility.py
  - Gateway compatibility test for the IDS.
  - Sends each message from `multi_device_dataset.json` through `IDS.detect()` and verifies normal messages remain normal and attack messages generate alerts.

Current status
--------------
- Legacy datasets and metric files were removed from the repository because they were no longer needed.
- The current test workflow is Gateway-focused and uses `multi_device_dataset.json` as the input source.
- The alert payload generation path is working: the multi-device dataset now produces a set of alerts for Data Injection, Device Spoofing, and DoS across four device types.
- `alert_payload.json` contains the sample-generated alerts for use by students, dashboards, or AI analysis.

What is happening now
----------------------
The code is being cleaned up to support the Gateway JSON schema and ensure downstream usage is simple:
- The IDS receives a message, validates its structure, and extracts the heart rate.
- If the message is valid and normal, the IDS returns None.
- If any rule matches, the IDS returns an alert object with a normalized schema.
- The Gateway sample file is used as the authoritative test input, and its generated alerts are written to `alert_payload.json`.
- This makes the system ready for discussion, integration, and demonstration with other AIs or professors.
